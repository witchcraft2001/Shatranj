# Sprinter tester notes — S0: infrastructure and dependency pins

Stage S0 delivers build infrastructure only. There is nothing to run on
Sprinter hardware or in MAME yet: the EXE is a stub that prints a banner
and exits. This protocol is a host-side verification of the build system.

## Prerequisites

- git, GNU make, Python ≥ 3.10
- z88dk (`z80asm` in PATH)
- mtools (`mformat`, `mcopy`, `mdir`)

## Protocol

### 1. Clean clone initializes pins from GitHub

```sh
git clone <repo> shatranj-s0 && cd shatranj-s0
git checkout sprinter
git submodule update --init --recursive
```

- [ ] All four submodules (`extern/esp_net`, `extern/rtl_net`,
      `extern/libman`, `extern/sprinter-libs`) fetch from GitHub without
      credentials.

### 2. Dependency gate

```sh
make sprinter-check
```

Expected output ends with:

```
Sprinter dependencies: OK
[OK] sprinter-check: deps, EXE format, smoke image (deterministic)
```

- [ ] `sprinter-check` is green.
- [ ] The run prints the EXE SHA-256 line
      (`[OK] SHATRANJ.EXE sha256 <digest> ...`) and the digest matches
      `shasum -a 256 release/Sprinter/SHATRANJ.EXE`.

### 3. Pin-drift trap check (gate must trap, not pass silently)

```sh
git -C extern/sprinter-libs checkout HEAD~1
make sprinter-deps-check   # MUST fail with a commit mismatch message
git -C extern/sprinter-libs checkout 2c58d793cda75dab7e0b2d2836221f089ad8660b
```

- [ ] The gate fails loudly on the moved pin and passes again after
      restoring it.

### 4. Artifacts

- [ ] `release/Sprinter/` contains `SHATRANJ.EXE`, `UNETESP.DLL`,
      `UNETRTL.DLL`.
- [ ] `build/sprinter/SHATRANJ-SMOKE.IMG` exists (FAT12, 1 474 560 bytes).
- [ ] Running `make sprinter-check` twice produces a byte-identical image
      (`shasum -a 256` before/after).

### 5. Optional: stub smoke on Sprinter/MAME

Not required for S0 sign-off. If the image is booted anyway, the stub must
print the two banner lines and return to the DSS prompt without hanging.
