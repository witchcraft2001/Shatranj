# S14 — piece sets and palettes

Use `build/sprinter/SHATRANJ-SMOKE.IMG` in MAME or extract
`build/sprinter/SHATRANJ-HW.zip` into one directory on hardware.
The ZIP contains the EXE and all three network DLLs.

The menu order is FILE, DISCC, RESET, FLIP, THEME, PIECES, ABOUT.
PIECES cycles California → MPChess → Totoy → California. A fresh launch
starts with California. Arrow navigation wraps through all seven tabs;
Enter and Space activate the focused tab. The last two tabs must appear
at the right side of the menu without wrapping to the left.

## Acceptance checklist

- Cycle all three sets in each of the five board themes. Check all twelve
  pieces on light and dark squares and during the move flash.
- Select a piece with legal-move hints visible, then change PIECES. The
  selection, hints and cursor must return at their previous model squares.
- Repeat while the board is flipped. Change THEME and confirm the piece
  shape and colours remain selected.
- Open and dismiss About, including the fades. The chosen set and theme
  must return. Check save/load, reset, disconnect and a new network game;
  these must retain the selected set until application exit.
- Restart the application and confirm California is selected again.

## Automated coverage

per-piece group location table from its packing results. Pixel round trips
cover all 108 committed tiles. The host menu test covers both six-tab
ZX/Next and seven-tab Sprinter navigation and Enter/Space actions.
The shipping Z80 menu overlay is tested for 300 switches, palette data,
theme isolation, staged labels and X coordinates above 255. Distinct

call through the real `video_init` verifies the selected colours survive. A separate

## Piece conversion: structural outlines (2026-10-31)

All 36 piece PNGs regenerated by `tools/rasterize_sprinter_pieces.py` with a
new outline policy. No hand edits — the committed PNGs are byte-identical to
a fresh run of the script (verified), so regeneration stays safe.

### Why

The tile is 40×20 on 1×2 pixels: one output row is 51 source pixels, and
every set's horizontal strokes are thinner than that (mpchess 0.8 rows,
totoy 0.95, california 1.2). The old pipeline decided each pixel by which
colour class covered the most area, so a stroke straddling two rows (40 % +
40 %) lost to the body in both and the outline vanished where it was
thinnest. The black-piece rim was derived at sub-pixel width (0.375 of a
row) and then thresholded at 50 % — it could never pass vertically, hence
the dotted rim. Measured over the 36 committed tiles before the change:

| | before | after |
| --- | --- | --- |
| white: silhouette-edge pixels without dark outline | 79 / 1511 (5 %) | **0** |
| black: silhouette-edge pixels without light rim | 942 / 1954 (48 %) | 287 / 1820 (16 %) |

The remaining 16 % is mpchess only: its black base and body are separate
source parts with a one-pixel gap, and the rim must not bridge them.
California and totoy are at 0–5 pixels per set.

### What the script does now

- Silhouette first (alpha ≥ 50 %, nine-phase search as before), then the
  outline derived from it at output resolution: white = the silhouette's
  own interior 4-boundary ring (index 5); black = exterior 4-boundary ring
  (index 7), topology-guarded (never bridges separate parts, never seals a
  passage; notches between crown spikes fill with rim colour, which
  differs from the body, so they stay readable).
- Interior detail lines from dark-stroke coverage at a 35 % threshold,
  thinned to **one row** wherever the source stroke is thinner than 1.5
  rows — a sub-row line lands on exactly one row instead of vanishing or
  doubling.
- All of it inside the phase search, so the phase is chosen for where the
  lines land. Source topology (parts, holes) is preserved for every piece
  (per-piece reports in `build/sprinter/preview/source1024/*.json`).

Tests: `tests/tools/test_rasterize_sprinter_pieces.py` gained five cases
(continuous white outline, continuous black rim with preserved topology,
rim fills a notch but never bridges parts, sub-row stroke → one row, ring
geometry); 41 pass. The build gate accepted all 36 PNGs unchanged in its
rules. `port.md` §4 step A.3 documents the policy.

### What to check in MAME

1. Every white piece has a continuous dark outline on the **light** square
   — the old build showed body touching the square on the california
   knight's head and a few other edges.
2. Every black piece has a continuous light rim on the **dark** square;
   on mpchess the gap between base and body stays open (by design).
3. Thin horizontal details — totoy king/queen base stripes, pawn collars,
   california crown ribs — read as single crisp lines, not doubled or
   missing.
4. Cycle PIECES through all three sets and all five THEMEs; the flash tile
   (move highlight) must show the same outlines.
